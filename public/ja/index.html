    ヘルプ

    このページは何を調べますか？

    ドメインを入力すると、9 種類のレコード（A、AAAA、CNAME、MX、NS、TXT、CAA、SRV、SOA）を 12 の公共リゾルバーに、ブラウザから DNS over HTTPS（DoH、暗号化された DNS）で同時に問い合わせます。同じ値はまとめ、各リゾルバーの応答は「リゾルバーの応答」に表示します。登録情報は RDAP（構造化された WHOIS）から取得します。

    健診の評価はどう決まりますか？

    評価は 2 つのうち低いほうです。1 つは応答がどれだけ揃っているか、もう 1 つはメール設定です。揃い具合は、応答したリゾルバーだけで数えます。応答したものがすべて同じなら A、1 つでも違えば B です。このページからつながらなかったリゾルバー（多くはお使いの回線のため）は、どちらにも数えません。リゾルバー自身が返す SERVFAIL や REFUSED は応答なので数えます。12 台中半分未満しか応答しなければ評価は出しません。メール評価は SPF と DMARC から出し、メールを受け取れる MX があるときだけ付けます。署名済みで DNSSEC の検証に失敗するドメインはもう 1 段下がります。CAA と IPv6 はバッジだけで、評価は変わりません。

    DNSSEC で何が分かりますか？

    DNSSEC があると、リゾルバーは応答が本当にそのドメインのもので、途中で書き換えられていないことを証明できます。ページは親ゾーンに DS レコードを問い合わせ、検証すると分かっているリゾルバーの AD ビットを読みます。「有効、検証済み」はドメインが署名済みで、そのリゾルバーがすべて認めたという意味です。「有効だが検証に失敗」は、署名済みのドメインの応答が検証を通らず、確認するリゾルバーやブラウザーが拒否する状態です。無効はよくある状態で、評価は下がりません。材料が足りないときは「判断できません」と書きます。

    レコードの変更はいつ反映されますか？

    レコードを変更しても、各リゾルバーは TTL（有効期間）が切れるまで古いコピーを使います。そのため変更直後は、新しい値を返すリゾルバーと古い値を返すリゾルバーが混ざり、「リゾルバーの応答」にどちらかが表示されます。ブラウザはドメイン自身の権威サーバー（53 番ポート）に接続できないため、ここで分かるのは公共リゾルバーのキャッシュの状態だけです。

    「接続できず」と出るのはなぜ？

    問い合わせはブラウザから各リゾルバーへ直接送られます。中国本土では Cloudflare と Google の DNS が通常つながらず、他の一部も同じです。その行は「接続できず」と表示します。これは経路の問題で、レコードが空という意味ではありません。応答しなかったリゾルバーは不一致として数えません。

    「同じ応答」と TTL は何ですか？

    「同じ応答」は、応答したリゾルバーのうち、最も多い応答を返した数を数えたものです。TTL はそのリゾルバーがレコードを保持できる残り時間で、zone の値から減っていきます。リゾルバーごとに残り時間が違うのは正常で、不一致ではありません。

    SPF と DMARC はどう確認しますか？

    SPF はドメインの TXT レコードから読みます。v=spf1 が複数ないか、末尾が +all、-all、~all、?all のどれか、もう一度 DNS を引く仕組み（include、a、mx、ptr、exists、redirect）がいくつあるか（上限 10）を確認します。include の先までは追わないため、この数は下限です。DMARC は _dmarc.<ドメイン> から、p= の方針、報告先（rua）の有無、pct を読みます。

    レジストリの NS とリゾルバーの NS が違うのはなぜ？

    レジストリ側（RDAP）は登録された情報で、リゾルバーが返すのはドメインが実際に公開している NS レコードです。違う場合は、変更がまだ反映中か、レジストリの情報が古いかのどちらかです。両方をそのまま表示します。

    RDAP とは？ 項目が空なのはなぜ？

    RDAP はレジストリが提供する構造化された WHOIS です。公開する情報が少ないレジストリもあり、プライバシー保護サービスが登録者情報を置き換えることもあります。欠けている項目は「なし」ではなく「不明」として表示します。

    登録情報をサーバーが代わりに取るのはなぜ？

    RDAP はレジストリごとに提供され、rdap.org は IANA のブートストラップに載っているサフィックスしか知りません。また、RDAP はあるのにブラウザーから読めないサフィックスもあります（.de の DENIC など）。どちらの場合もブラウザーでは読めないため、ページは 1ms.dog のサーバーに代わりを頼みます。サーバーはまず RDAP を試し、なければレジストリの 43 番ポート WHOIS に接続します（現在は .cn、.jp、.ru、.hk）。結果には「サーバーが代わりに取得」と表示します。サーバーはレジストリが公開している内容をそのまま返します。登録業者、日付、状態、ネームサーバーに加えて、登録者（組織または氏名）、メール、電話、レジストリの DNSSEC も表示します。レジストリが公開していなければ空のままで、作ったり隠したりはしません。レジストリの応答そのものは「生の応答」に入れています。.vn の WHOIS は応答しないため、レジストリへのリンクを出し、「なし」ではなく「調べられない」と書きます。

    問い合わせはどこに送られますか？

    DNS の問い合わせはブラウザから「リゾルバーの応答」に並ぶ各リゾルバーへ直接送られます。登録情報もまずブラウザが rdap.org かレジストリ自身の RDAP（.io など）に問い合わせます。ブラウザーで読めないとき（CORS のない RDAP、RDAP のないサフィックス）は、ページが 1ms.dog のサーバーに一度だけ代わりを頼みます。サーバーはまず RDAP、次にレジストリの 43 番ポート WHOIS を試し、結果には「サーバーが代わりに取得」と表示します。あなたの IP も問い合わせ内容もログに残しません。共有リンクにはドメイン自身の公開レコードと表示した登録情報だけが入り、あなたの IP も登録者や連絡先も入りません。

    共有リンクを開いても数値が変わらないのはなぜ？

    共有された結果はスナップショットで、その時点でリゾルバーが返した内容を表示します。二人が同じデータを見られるようにするためです。今の値を調べるには「自分の結果を調べる」を押してください。
