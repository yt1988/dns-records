    ヘルプ

    このページは何を調べますか？

    ドメインを入力すると、9 種類のレコード（A、AAAA、CNAME、MX、NS、TXT、CAA、SRV、SOA）を 12 の公共 DNS サーバーに、ブラウザから DNS over HTTPS（DoH、暗号化された DNS）で同時に問い合わせます。同じ値はまとめ、各サーバーの回答は「反映状況」に表示します。登録情報は RDAP（構造化された WHOIS）から取得します。

    DNS の反映（伝播）とは？

    レコードを変更しても、各 DNS サーバーは TTL（有効期間）が切れるまで古いコピーを使います。そのため変更直後は、新しい値を返すサーバーと古い値を返すサーバーが混ざり、「反映状況」にどちらかが表示されます。ブラウザはドメイン自身の権威サーバー（53 番ポート）に接続できないため、ここで分かるのは公共 DNS サーバーのキャッシュの状態だけです。

    「接続できず」と出るのはなぜ？

    問い合わせはブラウザから各 DNS サーバーへ直接送られます。中国本土では Cloudflare と Google の DNS が通常つながらず、他の一部も同じです。その行は「接続できず」と表示します。これは経路の問題で、レコードが空という意味ではありません。応答しなかったサーバーは不一致として数えません。

    一致率と TTL は何ですか？

    一致率は、応答した DNS サーバーのうち最も多い回答を返した割合です。TTL はそのサーバーがレコードを保持できる残り秒数で、zone の値から減っていきます。サーバーごとに残り時間が違うのは正常で、不一致ではありません。

    SPF と DMARC はどう確認しますか？

    SPF はドメインの TXT レコードから読みます。v=spf1 が複数ないか、末尾が +all、-all、~all、?all のどれか、もう一度 DNS を引く仕組み（include、a、mx、ptr、exists、redirect）がいくつあるか（上限 10）を確認します。include の先までは追わないため、この数は下限です。DMARC は _dmarc.<ドメイン> から、p= の方針、報告先（rua）の有無、pct を読みます。

    レジストリの NS と DNS サーバーの NS が違うのはなぜ？

    レジストリ側（RDAP）は登録された情報で、DNS サーバーが返すのはドメインが実際に公開している NS レコードです。違う場合は、変更がまだ反映中か、レジストリの情報が古いかのどちらかです。両方をそのまま表示します。

    RDAP とは？ 項目が空なのはなぜ？

    RDAP はレジストリが提供する構造化された WHOIS です。公開する情報が少ないレジストリもあり、プライバシー保護サービスが登録者情報を置き換えることもあります。欠けている項目は「なし」ではなく「不明」として表示します。

    問い合わせはどこに送られますか？

    DNS の問い合わせはブラウザから「反映状況」に並ぶ各サーバーへ直接送られます。RDAP は rdap.org に送られ、そこからレジストリへ転送されます。当社のサーバーは通りませんし、ログも残しません。共有リンクにはドメイン、表示したレコード、登録情報だけが入り、あなたの IP は入りません。

    共有リンクを開いても数値が変わらないのはなぜ？

    共有された結果はスナップショットで、その時点で DNS サーバーが返した内容を表示します。二人が同じデータを見られるようにするためです。今の値を調べるには「自分の結果を調べる」を押してください。

    DNSSEC、DKIM、証明書も確認しますか？

    この版では確認しません。表示するのは DNS サーバーが返したレコードです。DNSSEC の検証、DKIM セレクタ、証明書は別の確認項目で、別のツールで扱う予定です。
